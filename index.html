Why skills

A skill is the missing layer between a chatbot and a teammate.

Tools give an agent hands. Skills give it judgment: a reviewed playbook for how your team does a specific job, loaded only when it is needed.

01

Progressive disclosure

Only the name and description sit in context. The full playbook loads when the task matches, so your prompt budget stays clean.

02

Portable by design

A folder with a SKILL.md and its references. Works in a repo, a global config, or a zip you hand to a teammate.

03

Reviewable before install

Plain text is auditable. Check links, scripts, and permissions before the agent ever follows the instructions.

04

Manual or automatic

Advertising is a choice. Keep a skill manual-only until you trust it, then let the model discover it when the work fits.

05

Composable

One skill can point to references, templates, and scripts. Keep the main file short and let the agent read deeper only when needed.

06

No lock-in

No service, no account, no proprietary format. If you can copy a folder, you can move a skill.

How it works

Four steps from “interesting repo” to “installed, verified skill”.

The same loop works whether you use the CLI or do it by hand. The order matters: review before install, verify after.

1

Find the real skill folder

A skill is a folder containing SKILL.md. One repo can hold several skills; pick one deliberately.

2

Review and validate

Check frontmatter, companion links, scripts, secrets, and permissions. The validator catches broken links and missing files.

3

Install the whole folder

Copy it globally or into .opencode/skills. Choose manual-only until the skill has earned your trust.

4

Verify and restart

Restart opencode, then confirm the skill is registered and the advertised state matches the mode you chose.

           Safety
          
Install like you are reviewing code, because you are.

          
A skill is instructions an agent may follow with your tools and permissions. Treat it as executable text.

        


        

          
01
Read before you run
Open the SKILL.md, the scripts, and every companion file. If a step is opaque, stop.

          
02
Check the blast radius
What can it read, write, execute, and send? Start in a repository where a bad edit is recoverable.

          
03
Prefer manual-only
Do not advertise a new skill until you have used it once and seen how it behaves.

          
04
Pin and diff updates
Install from a tag or commit. Review the diff before replacing a working install.

          
05
Use least privilege
If a skill needs a token, scope it narrowly. Rotate it when the skill is no longer needed.

          
06
Report, don’t hide
If a skill is malicious or unsafe, do not install it. Tell the maintainer and your team.

           FAQ
          
Questions people ask before the first install.

        


        

          
Is a skill the same as an MCP server?
No. An MCP server exposes tools that are always in context. A skill is a playbook loaded on demand. Use MCP for live actions and skills for repeatable judgment.

          
Do I need Node.js?
Only for the optional CLI. A skill itself is a folder of Markdown and companion files. The website is static HTML, CSS, and JavaScript.

          
Where do skills live?
Globally in ~/.config/opencode/skills/<id>/SKILL.md, or per project in .opencode/skills/<id>/SKILL.md.

          
Why does a manual-only skill lose its description?
On opencode 1.x, only skills with a description are advertised to the model. Removing it hides the skill from automatic discovery while the command file keeps it callable.

          
How do I verify an install?
Restart opencode, run opencode debug skill, and find the skill ID. Check whether the description is present; that tells you whether it is advertised.

          
Is it safe to install a random skill?
Only after review. Read the instructions and scripts, check the blast radius, and start manual-only. A skill is not sandboxed by itself.

          
Can I use this without opencode?
The concepts and the builder are portable. The install paths and visibility flags are specific to opencode; adapt the folder layout for another agent that supports Agent Skills.
